## 2. 환경 구성

| 환경 | 목적 | 데이터 | 외부 연동 |
|---|---|---|---|
| dev | 개발자 로컬·공용 개발 | 시드 데이터 | PG·SMS 모의(Mock) 어댑터 |
| stg | 검증·인수시험 | 익명화 시험 데이터 | PG 테스트 상점, SMS 테스트 발신 |
| prod | 조리읍 운영 | 운영 데이터 | 계약된 PG·SMS·지도 |

- 환경별 설정은 환경변수와 `.env.{env}`로 분리하고, 비밀값(DB 비밀번호, PG 시크릿, AES 키)은 저장소에 넣지 않는다(RQ-SER-NF-008).
- 운영 배포는 검수 통과 빌드 산출물(커밋 해시·마이그레이션 리비전 고정)만 허용한다(RQ-QUR-NF-010).

### 2.1 운영 배포 단위 (자치회 1곳당)
```
[Nginx] ─┬─ user.{도메인}   → web-user 정적 빌드
         ├─ admin.{도메인}  → web-admin 정적 빌드 (관리자 IP 허용목록 권장)
         └─ /api, /pg/webhook → api (Gunicorn+Uvicorn ×N)
[worker]  APScheduler 단일 인스턴스 (만료·승격·SMS·파일검사·파기)
[MariaDB] 자치회 전용 스키마 + 전용 계정 (api용 / worker용 / 백업용 분리)
[파일저장소] 로컬 디스크 /data/files (DB 밖, 웹 루트 밖)
```

**설계 제약**
- 신청 생성은 강좌 행 잠금 구간을 최소화한다. 잠금 보유 시간 목표 50ms 이하.
- 강좌 목록은 공개 강좌만 대상이고 운영 규모(기수당 수십 강좌)상 캐시 없이 DB 인덱스로 충족 가능하다. 캐시를 쓸 경우 공개 상태 변경 시 즉시 무효화한다(RQ-SER-NF-009, RQ-QUR-NF-008).

## 4. 보안 요구

### 4.1 인증·세션 (RQ-SER-NF-008, FN-024)
| 항목 | 기준 |
|---|---|
| 비밀번호 저장 | PBKDF2-HMAC-SHA-256, 계정별 16바이트 이상 무작위 솔트, 반복 600,000회 이상 |
| 비밀번호 규칙 | 10~64자 (FN-062) |
| 로그인 실패 제한 | 회원: 직전 10분 이동 구간 5회 실패 → 해당 계정 15분 잠금. 누적 실패횟수 컬럼만으로 구간을 계산하지 않는다(AUTH-04). 관리자 수치는 승인된 관리자 정책(PRD Q28) |
| 회원 세션 | 유휴 30분 만료 |
| 관리자 세션 | 유휴 15분 만료 |
| 세션 방식 | 서버 세션(TB_LGN_SSN, 토큰 해시만 저장) + HttpOnly·Secure·SameSite=Lax 쿠키 ([ADR-008](ADR.md#adr-008)). Redis 등 추가 저장소 없음(스키마 B03) |
| 비밀번호 재설정 | 완료 시 해당 회원의 모든 세션 무효화 |
| 관리자 MFA | 범위 제외 |
| 전송 구간 | HTTPS, TLS 1.2 이상, HSTS |

### 4.2 본인확인 OTP (FN-029, FN-061, FN-062, FN-031)
| 항목 | 기준 |
|---|---|
| 형식 | 숫자 6자리, SMS 발송 |
| 유효시간 | 발급 후 5분 |
| 시도 제한 | 5회 오류 시 해당 코드 무효 |
| 재전송 | 최소 60초 간격 |
| 저장 | 코드 원문은 DB·로그·문자 저장 문안에 남기지 않는다. 별도 비밀키 HMAC 검증값과 키 버전만 저장한다(AUTH-03). 문안에는 자리표시자만 저장하고 발송 순간 메모리에서 결합한다 |

### 4.3 암호화·비밀값
| 대상 | 방식 |
|---|---|
| 수동환불 계좌번호·예금주 | AES-256-GCM 암호문 봉투(`VARCHAR(1024)`), 키는 환경변수/키 파일(DB 밖). 원거래 취소면 저장하지 않음 |
| 문자 수신번호·인증 전화번호·강사 지원 전화번호 | AES-256-GCM 암호문 저장, 화면·CSV 출력 시 마스킹 |
| 회원·관리자 휴대전화(`MBL_TELNO`) | 스키마상 `VARCHAR(11)` 평문 컬럼. 화면·CSV 출력 시 마스킹. 암호화 여부는 개인정보 영향 검토 후 결정(PRD Q27 관련) |
| 로그·감사이력 | 비밀번호·계좌 원문·OTP·SQL 원문 기록 금지 (RQ-SER-NF-005) |
| 개인식별 내보내기 | 암호 XLSX 또는 AES-256 ZIP, 암호는 별도 경로 전달 (FN-068) |

### 4.4 인가 (RQ-SER-NF-001, 003, 004, 009, FN-056)
- 모든 관리자 API는 `(기능 권한, 운영묶음 범위, 유효기간)`을 **같은 배정 건**에서 검사한다.
- 신청·결제·환불의 범위는 회원 거주 동이 아니라 **대상 강좌의 운영 동**으로 판정한다.
- 요청 본문·쿼리의 운영묶음 ID는 신뢰하지 않는다. 인증된 세션의 배정 정보로만 결정한다.
- 시스템 관리자 역할은 구조 관리(권한·코드·설정) 권한만 가지며 회원·결제 본문 조회는 별도 기능 권한이 필요하다.
- 권한 배정자는 자신이 보유한 범위·기간 안에서만 위임하고, 자기 권한 상승은 다른 승인자의 승인을 거친다.
- 목록·검색·첨부 다운로드·CSV·캐시·배치에 동일한 판정을 적용한다.

### 4.5 첨부파일 (RQ-SER-NF-002)
| 항목 | 기준 (Q9 확정 전 가정) |
|---|---|
| 허용 확장자 | pdf, hwp, hwpx, doc, docx, xls, xlsx, jpg, jpeg, png |
| 최대 크기 | 파일당 20MB |
| 검사 | 업로드 즉시 `FS.PENDING`, 워커가 ClamAV 검사 후 `FS.SAFE`/`FS.BLOCK` |
| 소유자 | 파일당 소유 업무 정확히 하나(10종), 같은 운영묶음 (FILE-10) |
| 다운로드 조건 | `FS.SAFE` + 소유 업무 존재 + 소유 업무의 현재 공개·권한 + 동일 운영묶음. 감면 증빙·만족도 원자료·강사 지원 증빙은 비공개 |
| 저장 경로 | 웹 루트 밖, `STRG_KEY`는 묶음 접두부 + 난수 객체키, 원본명(`FILE_NM`)은 DB에만. 서명 URL·절대경로는 저장하지 않음 |
| 감사 | 요청 ID·행위자·IP·파일 ID·시각·허용/거절 기록 |

### 4.6 입력 검증·시큐어코딩 (RQ-SER-NF-007)
- 모든 입력은 Pydantic 스키마로 서버 검증한다(날짜 실재, 기간 순서, 금액 ≥ 0, 정원 ≥ 1, 문자열 길이).
- 문자열 길이는 **문자 수와 바이트 수를 함께** 검사한다(utf8mb4 컬럼 한도).
- SQL은 ORM 바인딩만 사용한다. 원시 SQL은 리뷰 필수.
- 출력은 React 기본 이스케이프를 쓰고, 게시물 본문 HTML은 허용목록 기반 정화(bleach 등) 후 저장한다.
- CSV는 `= + - @ \t \r`로 시작하는 셀 앞에 `'`를 붙여 수식 주입을 막는다(FN-068).
- 정적 분석: Bandit(Python), ESLint security 규칙, 의존성 취약점 점검(pip-audit, npm audit). 결함은 심각도·조치·재검증 결과를 기록한다.
- 행정안전부 「소프트웨어 개발보안 가이드」 49개 항목 중 해당 항목을 점검표로 관리한다.

법정 보존 의무가 더 길면 그 기준을 우선한다.

| 대상 | 운영 DB, 첨부파일, 환경설정, 정산자료 |
| 전체 백업 | 일 1회 (mariabackup) |
| 증분 | 최대 15분 간격 (바이너리 로그 전송) |

| 복구시험 | 월 1회, 회원·강좌·신청·결제·환불 건수·금액과 첨부 연결 대조 |

### 5.3 데이터 경계 (RQ-DAR-NF-001)
- 자치회마다 독립 DB 스키마·계정을 쓴다. 센터 간 JOIN·합산·복제 금지. 모든 자치회 DB에 같은 스키마·코드집합 버전을 적용한다(스키마 R24).
- 스키마는 45테이블·610컬럼·184FK이며 논리 설계다. 실제 MariaDB 생성·변경은 스키마 9.1 순서(버전 조사, 물리 DDL 확정, 백업, 마이그레이션, 규칙 시험)로 한다.
- 한 자치회 DB 안에서도 모든 업무 테이블은 `OPER_BNDL_SN`(운영묶음)을 갖고 조회 조건에 포함한다.
- 회원의 기준 동은 관리 정보일 뿐 거주 자격 인증이 아니다.

### 5.4 이관 (RQ-DAR-NF-002)
- 강좌·시설·강사 기초자료만 지정 서식(xlsx)으로 받아 검증 후 등록한다.
- 과거 회원·신청·결제·환불 원장 이관은 하지 않는다(변경관리 대상).

### 5.5 자료 진실성 (RQ-QUR-NF-001, RQ-QUR-NF-006)
- 화면에 임의의 강좌·인물·금액·날짜를 생성해 표시하지 않는다. 값이 없으면 빈 상태 또는 "확인 필요"로 표시한다.
- 시드 데이터는 dev/stg 전용이다. 스키마에 시드 표시 컬럼이 없으므로 배포 파이프라인이 prod에 시드 마이그레이션을 싣지 않고, 운영 DB 적재는 검증 스크립트를 통과한 기준자료만 허용한다.
- 미확인 거주지·미매핑 분류·과거 집행자·자리배정시각 등은 추정해 채우지 않고 NULL 또는 미확인 코드로 둔다(스키마 1.2).
- 결제·환불 "완료"는 PG 검증 또는 집행 결과 확인 후에만 표시한다.

## 6. 외부 연동

모든 외부 연동은 어댑터 인터페이스 뒤에 둔다. 공급자가 확정되면 구현체만 추가한다([ADR-009](ADR.md#adr-009)).

| 연동 | 인터페이스 | 필수 기능 | 공급자 |
|---|---|---|---|
| PG | `PaymentGateway` | 결제창 요청, 승인 확인(서버 대 서버), 거래 조회, 전체/부분 취소, 웹훅 서명 검증 | TBD (토스페이먼츠 / KG이니시스 / NHN KCP) |
| SMS | `SmsSender` | 단건·다건 발송, 발송 결과 조회, 요청 멱등키 | TBD (NHN Cloud / 알리고 / 솔라피) |
| 지도 | 프런트엔드 SDK | 승인된 센터 좌표 표시, 로딩 실패 시 주소 텍스트 대체 | TBD (카카오맵 / 네이버 지도) |
| 바이러스 검사 | `FileScanner` | 파일 스트림 검사 | ClamAV |

**PG 연동 필수 조건 (FN-040~042)**
- 결제 결과는 브라우저 리다이렉트 값을 믿지 않고 서버가 PG 승인 API로 금액·통화·가맹점·주문번호를 대조한 뒤 반영한다.
- 웹훅은 서명 검증 후 수신 원문 해시와 함께 저장하고 멱등 처리한다.
- 응답 유실 시 원주문번호로 재조회 3회. 그래도 미확정이면 `결과 확인 중`.
- 결제수단은 신용·체크카드, 실시간 계좌이체만 허용한다.

**SMS 문구 제약 (FN-028)**
- 승격 알림에 강좌명·배정시각·결제마감시각·신청내역 링크만 포함한다. 개인정보·결제수단은 넣지 않는다.
