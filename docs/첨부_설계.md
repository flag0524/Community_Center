# 첨부·내보내기 설계

관리자·주민 화면 여러 곳이 "첨부 기능이 생기면 더한다"로 미뤄 둔 부분을 한 번에 정리한다. 파일 올리기·내려받기와 감사기록, 증빙 제출, 이미지, 목록·통계 CSV와 개인식별 명단 내보내기가 범위다. 스키마(TB_FILE)와 TDD 8.4·8.6, TRD 4·5가 이미 정한 것은 그대로 따르고 이 문서는 그 위에서 비어 있는 부분을 채운다. 결정은 9절에 모았고 사용자가 2026-11-07에 확정했다.

## 1. 이미 정해진 것

| 항목 | 내용 | 근거 |
|---|---|---|
| 허용 확장자·크기·검사 | pdf, hwp, hwpx, docx, xlsx, jpg, png, 파일당 20MB, ClamAV 비동기 검사 (기관 확인 전 가정) | PRD Q9 |
| 파일 상태 | 올리면 `FS.PENDING`, 워커가 10초마다 검사해 `FS.SAFE` 또는 `FS.BLOCK`. 삭제는 `FS.DELETE` | TDD 7.4 |
| 소유자 | 파일 하나는 소유 업무 하나에만 속한다. 소유자 없는 임시 파일 행을 만들지 않는다 | FILE-10 |
| 저장 | 웹 루트 밖. `STRG_KEY`는 묶음 접두부 + 난수 객체키. 원본 이름은 DB에만 두고 경로·서명 URL은 저장하지 않는다 | TRD 4 |
| 내려받기 조건 | 검사 통과 + 소유 업무 존재 + 소유 업무의 현재 공개·권한 + 같은 운영묶음. 감면 증빙·만족도 원자료·강사 지원 증빙은 비공개 | TDD 8.4 |
| 응답 헤더 | `Content-Disposition: attachment`, `X-Content-Type-Options: nosniff`, `Cache-Control: private, no-store` | TDD 8.4 |
| CSV | 목록과 같은 조건·권한, UTF-8 BOM, 수식 주입 방지, 첫 줄에 조건 메타 | TDD 8.6 |
| 내보내기 금지 | 출석 현황·상세, 만족도 자료 | FN-064, DGSTFN-03 |
| 개인식별 명단 | `AU.EXPORT` + AES-256 ZIP 또는 암호 XLSX, 암호는 파일과 다른 경로로 전달, 생성·내려받기 감사기록 | ADR-026 |

| 수강신청 | APPLICATION | | | | 쓰는 화면 없음 | 이 단계에서 다루지 않음 |

관리자 파일 조회 화면(`/mbr/files`)은 이미 있다. 올리기는 각 소유 업무 화면에서 하고 이 화면은 조회 전용으로 둔다.

## 3. 올리기

### 3.1 방식

업무를 먼저 저장하고 그 다음에 파일을 올린다.

```
POST /{owner}/{ownerId}/files    multipart/form-data, 파일 한 개 → FileSummary(상태 PENDING)
```

- 신규 업무도 먼저 저장해 소유자를 만든 뒤 파일을 올린다. 소유자 없는 임시 파일 행을 만들지 않는다는 FILE-10을 지키고 업무 저장 API는 지금처럼 JSON으로 둔다.
- TDD 8.4는 "신규 업무는 업무 저장 요청에 파일을 함께 받는다"고 적었으나 이 문서가 바꾼다. 업무 저장은 멱등키와 낙관적 잠금을 쓰는 JSON이고 큰 파일이 실패해도 입력한 내용을 잃지 않게 하려는 이유다. 9절의 결정 1.
- 파일 하나씩 올린다. 여러 개는 화면이 순서대로 올리고 진행과 실패를 파일별로 보인다.
- 업무 저장 전에는 "파일은 저장한 뒤에 추가할 수 있습니다"를 안내한다.

### 3.2 검증

| 검사 | 규칙 |
|---|---|
| 확장자 | 허용 목록에 있는지. 대소문자 무시 |
| 형식 확인 | 앞부분(매직 바이트)이 확장자와 맞는지. 맞지 않으면 거절 |
| 크기 | 20MB 이하, 0바이트 거절. 스트림으로 받아 초과하면 즉시 끊는다 |
| 파일명 | 경로 문자 제거, NFC 정규화, 128자를 넘으면 절단하지 않고 거절 |
| 개수 | 소유 업무 하나당 10개(가정, 9절의 결정 2) |
| 권한 | 소유 업무를 바꿀 권한과 같은 묶음·범위. 소유자가 없거나 남의 것이면 404 |
| 상태 | 소유 업무가 잠긴 상태(결정된 감면, 환불 승인 이후 등)면 추가·제거 거절 |

오류는 기존 형식(`{code, message, fields, requestId}`)을 쓰고 화면은 거절된 파일 이름과 이유를 파일별로 보인다.

### 3.3 검사와 상태

- 올리면 `FS.PENDING`. 워커가 clamd로 검사해 `FS.SAFE` 또는 `FS.BLOCK`으로 바꾼다. 차단 사유는 "악성코드가 의심됩니다" 한 문장만 담고 탐지 이름은 노출하지 않는다.
- 검사 서비스가 응답하지 않으면 상태를 바꾸지 않고 다시 시도한다. 오래 `PENDING`인 파일은 매일 03:00 일관성 점검(TDD 7.5)이 운영 업무로 올린다.
- `PENDING`·`BLOCK` 파일은 내려받을 수 없고 소유 업무 화면에서는 상태(검사 중·차단)만 보인다.

## 4. 내려받기와 감사기록

파일 정보(JSON)는 `GET /files/{id}`, 내용은 `GET /files/{id}/download`로 나눈다. 정보 API가 이미 있어 내려받기에 `/download`를 붙였다.

```
GET /files/{id}/download    판정 → X-Accel-Redirect 전송
```

- 판정은 파일이 아니라 **소유 업무의 현재 상태**로 한다. 게시물이 비공개로 바뀌면 첨부도 즉시 막힌다. 권한이 없거나 없는 파일은 같은 404로 답한다.
- 공개 업무의 첨부(공개 게시물, 공개 강좌의 강의계획서, 홈 이미지)는 로그인 없이 받을 수 있고 감사기록을 남기지 않는다(조회량이 많고 누구인지 알 수 없다).
- 비공개 파일(증빙, 원자료)과 관리자의 모든 내려받기는 내려받는 사람·시각을 기록한다. 기록은 관리자 파일 상세의 내려받기 기록과 감면 상세의 열람 기록에 보인다. 9절의 결정 3.
- 감면 상세의 `evidence-views`(열람 기록만 남기는 API)는 이 내려받기가 대신한다. 파일이 실제로 생기면 별도 열람 API는 없앤다.

## 5. 제거와 잠금

| 소유 업무 | 파일 추가·제거 |
|---|---|
| 게시물 | 담당자가 수정할 수 있는 동안 가능. 제거는 논리삭제(`FS.DELETE`)이고 물리 삭제는 보존기간 뒤 |
| 강좌 강의계획서 | 강좌를 수정할 수 있는 동안 가능 |
| 홈·센터 콘텐츠 | 수정할 수 있는 동안 가능 |
| 감면 사전심사 증빙 | 접수 상태일 때만 회원이 추가. 승인·반려 뒤에는 덮어쓰지 않고 재심사는 새 건에서 새 증빙(RDCT-BFHD-01). 증빙이 없으면 승인할 수 없다 |
| 환불 증빙 | 접수·보류 상태에서 담당자만 추가. 승인 뒤에는 잠금 |
| 강사 지원 증빙 | 지원서가 수정 가능한 동안 지원자가 추가·제거 |

제거는 파일 행을 지우지 않고 `FS.DELETE`로 바꾼다. 같은 요청 안에서 업무 이력(작업이력)에 남긴다.

## 6. 내보내기

### 6.1 목록·통계 CSV

```
GET {목록 경로}/export.csv    현재 조건 그대로, 페이지 제한만 해제
```

- 같은 쿼리 빌더와 같은 권한을 쓰고 응답은 스트리밍한다. 별도 저장은 하지 않는다.
- 상한은 5만 행이다. 넘으면 거절하고 조건을 좁히라고 안내한다(9절의 결정 4).
- 첫 줄에 조건 메타(기간·상태 기준일·집계 기준·생성 시각)를 주석 행으로 넣는다(통계). `= + - @ \t \r`로 시작하는 셀은 앞에 `'`를 붙인다.
- 만들 때마다 작업이력에 남긴다(누가·어떤 목록·조건·건수).

허용하는 화면은 수강신청, 결제·거래, 환불, 게시물, 문의, 강좌, 교육기수, 수요·정산 통계, 연령·성별 통계다. 연령·성별 통계의 CSV는 승인된 집계 자료만 담는다. 출석 현황·상세와 만족도는 내보내기 자체를 만들지 않는다.

### 6.2 개인식별 명단

```
POST /exports/pii    AU.EXPORT, 멱등키, 대상 목록과 조건 → AES-256 ZIP 응답 + 암호 1회
```

- 회원·신청자 명단처럼 이름·연락처가 들어가는 목록이 대상이다. 가려진 값이 아니라 실제 값을 담으므로 일반 CSV와 분리한다.
- 파일을 서버에 남기지 않는다. 요청 한 번에 만들어 바로 내려보내고 임시 파일은 응답이 끝나면 지운다. 따라서 새 테이블이나 소유자 코드가 필요 없다.
- 암호는 응답에서 한 번만 화면에 보인다. 담당자 휴대전화 SMS로 보내는 방식은 SMS 아웃박스와 겹쳐 이 단계에서 만들지 않는다.
- 상한은 5천 행이다. 생성 사실(누가·무엇을·몇 건)을 감사기록에 남긴다.

구현에서 정한 것(2026-11-08, 사용자 확정은 대상 목록과 모의 ZIP 방식).

- 대상은 회원 목록과 수강신청 목록이다. `AU.EXPORT`와 대상 목록의 조회 권한·범위를 함께 검사한다.
- 응답은 ZIP 본문과 `X-Export-Password` 헤더다. 서버가 암호를 보관하지 않으므로 같은 멱등키로 다시 보내면 409이고 다시 받으려면 새 요청을 한다.
- 모의 서버는 개발 전용 zip.js로 실제 AES-256 ZIP을 만든다. 운영 서버의 실제 구현(예: Python `pyzipper`)은 백엔드 단계에서 따로 한다.
- 암호 전달 방식과 `AU.EXPORT`를 가질 역할은 기관 확인 대상이다(요청서 R25).

## 7. 계약과 화면의 변경

| 구분 | 변경 |
|---|---|
| 계약 | `FileOwnerKind`에 `REDUCTION`, `SATISFACTION_SOURCE` 추가. `POST /{owner}/{ownerId}/files`, `DELETE /files/{id}`, `GET /files/{id}`, 목록별 `export.csv`, `POST /exports/pii` 추가. 감면 `evidence-views` 제거 |
| 관리자 화면 | 게시물·강좌·콘텐츠 양식에 파일 영역, 환불 접수 증빙, 감면 상세 내려받기, 파일 상세의 내려받기, 각 목록의 CSV 버튼, 개인식별 명단 내려받기 |
| 주민 화면 | 문의 첨부, 감면 신청 증빙, 강사 지원 증빙, 첨부 내려받기 오류 표시 |
| 공통 | 파일 영역 컴포넌트(선택·진행·거절 사유·검사 상태·제거), 내려받기 링크 |

## 8. 구현 순서

1. 파일 기반(계약, 공통 컴포넌트, 모의 서버) + 관리자 게시물 첨부와 강의계획서, 파일 조회 화면 연결.
2. 증빙(감면 신청, 감면 상세 내려받기, 환불 접수, 강사 지원서).
3. 홈·센터 콘텐츠 이미지.
4. 목록 CSV.
5. 개인식별 명단 내보내기.

각 단계는 계약 시험, 단위 시험, 브라우저 시험, 변이 검사를 거쳐 따로 커밋한다.
