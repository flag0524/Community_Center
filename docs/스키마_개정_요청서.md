# DB 스키마 개정 요청서 (초안)

대상은 `PRJ_2026_002_DB스키마_설계안.md` v0.5다. 작성일 2026-10-31이며 발송은 사용자가 한다. 승인 전에는 새 테이블·코드를 쓰지 않는다.

## 1. 확정된 요청 (intent.md D8, D9)

| 번호 | 요청 | 관련 RQ | 이유 | 승인 전 처리 |
|---|---|---|---|---|
| R1 | 권한 코드 `AU.CONF_W` 추가 (교육기수 관리) | RQ-FUN-FN-047 | 기수 관리 권한 코드가 없다 | 기수 관리 기능 보류 |
| R2 | 권한 코드 `AU.CORS_W` 추가 (강좌분류 관리) | RQ-FUN-FN-058 | 분류 관리 권한 코드가 없다 | 분류 관리 기능 보류 |
| R3 | 콘텐츠 유형(CT)에 수강문의·운영시간·주차 안내 추가 | RQ-FUN-FN-011, FN-072 | CT 코드에 이용약관·개인정보동의문·마케팅동의문만 있다 | 센터 전화·주소만 `TB_OPER_BNDL`에 표시 |
| R4 | 콘텐츠 유형(CT)에 개인정보처리방침·이메일무단수집거부 추가 | RQ-FUN-FN-055, FN-072 | 해당 유형이 없다 | "검토 중" 문구로 게시 |

## 2. 일괄 요청 후보 (PRD Q21, 사용자 확정은 "한 번에 요청")
권한 코드를 신설할지 기존 코드로 묶을지 기관과 설계 담당자의 판단이 필요하다.

| 번호 | 업무 | 관련 RQ |
|---|---|---|
| R5 | 감면 사전심사 | RQ-FUN-FN-038 |
| R6 | 공통코드 표시명 관리 | RQ-FUN-FN-069 |
| R7 | 보존·파기 검토 | RQ-SER-NF-006 |
| R8 | 집계자료 등록·승인 | RQ-FUN-FN-060 |

## 3. 요청하지 않는 것 (확정)
- 전화번호 검색키 컬럼 (D10)
- 환불 접수 채널 컬럼 (D11)

## 4. 별도 확인 (스키마 개정이 아님)
- 관리자 로그인 실패 제한 수치 (D12, PRD Q28). 기관 정책이 필요하다.
| R9 | 콘텐츠 유형 코드 CT.GUIDE(수강·환불 안내)와 CT.FACILITY(시설안내) 추가 | RQ-FUN-FN-006 | 안내·센터소개 글을 서버 콘텐츠 API로 내려주는데 현재 CT에는 소개·연혁뿐이다 | 두 글은 CT.INTRO·CT.HISTORY 값으로 임시 저장하지 않고 모의 서버 문서로만 둔다 |
| R10 | 회원의 본인 입력 거주지역 컬럼 추가(조리읍 / 그 외 파주시) | RQ-FUN-FN-031 | 시안의 회원정보수정이 거주지역 선택을 갖는데 TB_MBR에는 센터가 확인한 거주구분(HAB_RGN_CD)만 있고 회원의 자가 입력과 구분하라고 되어 있다. 자가 입력 값을 둘 곳이 없다 | 화면은 본인 입력(참고용)으로 두고 우선접수 판정에는 쓰지 않는다. 모의 서버에만 저장한다 |
| R11 | 게시판 설정에 "비공개 글 허용" 컬럼 추가 | RQ-FUN-FN-052 | 화면설계서 ADM-MBR-002S는 게시판별 회원 작성·답변·첨부·비공개 허용·사용 여부를 정한다고 하는데 TB_BBS에는 회원 작성·답변·첨부·사용 여부 네 정책만 있다. 비공개는 글(PRVT_YN)에만 있어 게시판 정책으로 막을 수 없다 | 게시판 설정 화면은 스키마의 네 정책만 다루고 비공개 허용은 화면에 넣지 않는다 |
| R12 | 회원 검토 기록(이용제한·탈퇴·이름 변경 사유와 처리 완료)의 저장 위치 | RQ-FUN-FN-065 (PRD Q25) | AU.MBR_W가 비활성이고 전용 테이블이 없다. 검토 상태(검토 중·처리 완료)를 구분해 남겨야 한다 | 작업이력(TB_JOB_HSTRY) 기록으로만 가정하고 모의 서버가 검토 기록으로 흉내 낸다. 이름 변경을 회원 정보에 반영하는 경로는 정해지지 않았다 |
| R13 | 거주지 확인 결과를 기록할 수 있는 권한 코드 | RQ-FUN-FN-025 (PRD Q5) | 회원 상세에서 센터 담당자가 거주지 확인 결과를 기록하는데 확인 수행 권한 코드가 스키마에 없다 | AU.MBR_R로 가정해 기록만 남기고 코드는 만들지 않는다 |
