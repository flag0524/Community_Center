# 기관 회신 요청 요약

조리읍 주민자치센터 수강시스템 구축에서 설계 담당자와 기관 담당자의 판단이 필요한 항목을 한곳에 모았다. 개발은 아래 "지금 가정"으로 계속 진행하고 있으며, 회신에 따라 해당 부분만 고친다. 항목 번호(R)는 [스키마 개정 요청서](스키마_개정_요청서.md)의 번호이고 Q는 PRD의 미결 질문 번호다. 회신 칸이 비어 있으면 "지금 가정"을 그대로 쓴다.

## 1. 관리자 권한 코드: 새로 만들지, 기존 코드로 묶을지

스키마에 권한 코드가 없는 업무가 여덟 개 있다. 현재는 새 코드를 만들지 않고 아래 기존 코드로 묶어 두었다.

| 업무 | 지금 가정(기존 코드) | 정할 것 | 번호 | 회신 |
|---|---|---|---|---|
| 교육기수 관리 | `AU.CONF_W` 신설 제안 | 신설 여부 | R1 | |
| 강좌분류 조회·변경 | 조회 `AU.CORS_R`, 변경 `AU.CORS_W` | `AU.CORS_W` 신설 여부 | R2, R21 | |
| 감면 사전심사 | 조회 `AU.APLY_R`, 심사·증빙 열람 `AU.APLY_W` | 신청 처리와 분리한 전용 코드 필요 여부 | R5, R19 | |
| 운영 설정 조회 | `AU.SITE_W` | 조회 권한 코드 | R6, R20 | |
| 공통 코드 표시명 수정 | `AU.GRANT_W` | 수정 권한 코드 | R6, R20 | |
| 보존·파기 검토 | 조회 `AU.LOG_R`, 실행 `AU.GRANT_W` | 조회·실행 권한 코드 | R7, R22 | |
| 거주지 확인 결과 기록 | `AU.MBR_R` | 확인 수행 권한 코드 | R13, Q5 | |
| 통계 집계자료 등록·승인 | 화면 없음(조회만 구현) | 권한 코드와 화면 위치 | R8, Q21 | |

## 2. 콘텐츠·약관 유형 코드(CT)를 한 번에 추가할지

현재 코드는 이용약관·개인정보 동의문·마케팅 동의문뿐이다. 구현에서는 아래 유형을 제안 코드로 쓰고 있다. 승인되면 이름만 맞추면 된다.

| 추가 제안 | 쓰임 | 번호 |
|---|---|---|
| `CT.GUIDE`, `CT.FACILITY` | 수강·환불 안내, 시설안내 | R9 |
| `CT.VISUAL`, `CT.CONTACT` | 홈 비주얼, 연락처(수강문의·운영시간·주차·주소) | R3, R14, Q23 |
| `CT.PRIVACY_POLICY`, `CT.EMAIL_REFUSAL` | 개인정보처리방침, 이메일 무단수집 거부 | R4, R16, Q24 |

## 회신이 없을 때 생기는 일

- 권한 코드 항목은 기존 코드 묶음으로 운영되며, 나중에 신설하면 배정 데이터를 옮겨야 한다.
- 컬럼 추가 항목은 위 가정대로 동작하고 해당 기능은 제한된 채 출시된다.
- 정책·값 항목은 표시 문구가 `TBD`·`검토 중`으로 남아 운영 시작 전에 채워야 한다.
