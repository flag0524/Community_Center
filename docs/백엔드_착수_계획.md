# 백엔드 착수 계획

독자는 내부 개발팀이다. 프런트(주민 앱·관리자 앱)와 API 계약(OpenAPI)이 끝나 계약 뼈대의 `not_implemented()`를 실제 구현으로 바꾸는 단계다. 근거는 [스키마 설계안](PRJ_2026_002_DB스키마_설계안.md) 9.1 "실제 DB 적용 순서"와 [TDD](TDD.md) 5·6·7절이다. 2026-11-08에 정했다.

## 1. 목표와 하지 않는 것

- 목표. 45개 테이블을 실제 MariaDB 10.11에 마이그레이션으로 만들고, 계약의 각 엔드포인트를 실제 DB 위에서 동작시킨다. 프런트 모의 서버(MSW)에만 있던 업무 규칙을 서버 시험으로 옮긴다.
- 하지 않는 것. 새 테이블·코드·권한 코드를 만들지 않는다(필요하면 스키마 개정 요청서에 올린다). 범위에서 빠진 기능(취소·미결제 자동 차단, 가상계좌, 관리자 MFA 등)은 만들지 않는다. 실제 PG·SMS 연동은 계약 후 값이 정해질 때까지 어댑터 뒤에 모의로 둔다(값을 지어내지 않는다, RQ-QUR-NF-001).

## 2. 단계

| 단계 | 내용 | 끝났다는 증거 |
|---|---|---|
| B0 환경 | 이식형 MariaDB 10.11을 확보해 로컬에서 띄우고 Python 의존성(SQLAlchemy 2·Alembic·PyMySQL)을 더한다 | 기동·종료 스크립트, 버전·문자셋 확인, 연결 시험 |
| B1 DDL 생성 | 스키마 설계안 4절의 표를 읽어 마이그레이션 SQL을 생성한다. 손으로 옮기지 않는다 | 생성기가 45 테이블·610 컬럼·184 FK·코드 40집합 182값·규칙 135건을 문서와 대조해 일치를 확인 |
| B2 DDL 적용 검증 | 빈 DB에 적용하고 `information_schema`로 다시 읽어 문서와 비교한다. 9.2 핵심 검수 사례 중 DB가 하는 것(조건부 UQ, 복합 FK의 다른 묶음 차단, CHECK)을 시험한다 | 적용·되돌림 성공, 구조 일치 시험, 제약 시험 통과 |
| B3 기반 계층 | DB 세션 의존성, 운영묶음 판정, 낙관적 잠금·멱등키 공통부, 오류 매핑 | 계약 시험과 DB 시험 통과 |
| B4 수직 구현 | 아래 3절 순서로 엔드포인트를 구현한다. 각 단계는 실제 DB 시험을 가진다 | 단계별 시험, 프런트 모의 규칙과의 일치 |
| B5 워커 | 만료·승격·SMS 발송·정리 배치(TDD 7절) | 동시성·중복 실행 시험 |

## 3. 구현 순서(B4)

핵심 위험이 큰 것을 앞에 둔다. 앞 단계가 뒤 단계의 전제다.

1. 인증·세션(회원 OTP·로그인·잠금, 관리자 로그인, 세션 만료). 모든 API의 전제다.
2. 공개 조회(홈·강좌·게시판·콘텐츠). 읽기만 해서 위험이 작고 프런트를 실제 API에 붙여 보기 좋다.
3. 신청·정원·대기·자동 승격(ADR-028). 가장 어려운 동시성이다. 마지막 1석 동시 신청과 대기자 우선을 시험한다.
4. 결제(PG 어댑터, 600초 기한, 결과 불명 `PS.PENDING`, 통보 중복·역순).
5. 환불(한도 검사, 예약, 동시 부분환불).
6. 관리자 업무(강좌·기수·회원·게시물·문의·콘텐츠·약관·권한 배정·감면·통계·SMS·설정).
7. 파일·CSV·개인식별 명단 내보내기.

## 4. 이 단계에서 정할 물리 사항(스키마가 "물리 DDL에서 정한다"고 미룬 것)

결정은 구현 전에 ADR-029로 남긴다.

- 일련번호 생성. `NUMERIC(22,0)` 컬럼에 값을 어떻게 채울지(MariaDB `SEQUENCE` 후보).
- 조건부 UNIQUE(`UQ_FILTER_ATNLC_APLY_01`, `UQ_FILTER_STLM_01`). MariaDB에는 부분 인덱스가 없어 생성 컬럼 방식이 후보다.
- 문자셋·정렬규칙(`utf8mb4` / `utf8mb4_unicode_ci`, TDD 6.1)의 최종 확인.
- 시각 저장(`_DT`는 UTC)과 서버 시간대 설정.

## 5. 위험과 대응

| 위험 | 대응 |
|---|---|
| 이 PC에 Docker·MariaDB가 없다 | 이식형 MariaDB 10.11(공식 보관소, 서명·해시 확인)을 프로젝트 밖 폴더에 두고 로컬 포트로만 연다. 운영(Ubuntu)과 같은 10.11이라 DDL 문법 차이가 없다 |
| 문서를 DDL로 옮기다 틀린다 | 생성기와 문서 숫자 대조, 적용 후 DB를 다시 읽어 대조 |
| 동시성 시험이 간헐적으로 통과한다 | `concurrency` 표시 시험을 따로 두고 여러 번 반복해 돌린다 |
| 프런트 모의 규칙과 서버가 어긋난다 | 단계마다 모의 서버 규칙을 서버 시험으로 옮기고 계약 시험을 유지한다 |
| 비밀값이 저장소에 들어간다 | 연결 정보는 환경변수·미커밋 파일만 쓴다(스키마 C09) |
