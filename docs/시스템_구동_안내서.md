# 조리읍 주민자치센터 수강시스템 구동 안내서

> 계정 정보와 개발 PC에서 시스템을 띄우는 방법 (2026-11-24 기준, 5.8절의 켜기·끄기 파일은 2026-11-26)

이 문서는 내부 개발팀이 개발 PC(Windows)에서 시스템을 띄우고 로그인해 보는 데 필요한 내용을 모았습니다. 계정 값은 모의 서버 소스(`mocks/auth.ts`)와 저장소 문서(`spec.md`)에 있는 개발용 가상 값이며, 운영 계정이 아닙니다.

## 1. 구동 방식 두 가지

| 구분 | 모의 서버 모드 (기본) | 실제 API 모드 |
|---|---|---|
| 필요한 것 | Node.js, pnpm | 위에 더해 Python(uv), MariaDB, 최초 설정(bootstrap) |
| 데이터 | 브라우저 메모리 (MSW). 쪽을 새로 열면 처음 상태 | MariaDB `jori_dev`에 저장 |
| 계정 | 개발용 가상 계정 4개가 바로 있음 | 새 DB는 계정이 없음(최초 관리자를 직접 만듦). 이 PC의 `jori_dev`에는 이미 있음 (2.2절) |
| 주민 로그인 | 가능 (`demo-member`) | 개발용 계정 도구로 만든 계정으로 가능 (5.5절) |
| 용도 | 화면 확인, 시연 | API·DB·워커까지 연결한 확인 |

> **참고** 처음이라면 모의 서버 모드부터 쓰세요. 설정 없이 몇 분 안에 두 화면 모두에 로그인할 수 있습니다. 실제 API 모드는 처음 준비를 마친 PC라면 파일을 두 번 눌러 켜고 끕니다(5.8절).

## 4. 방법 A. 모의 서버로 띄우기 (권장)

API와 DB 없이 두 화면을 띄웁니다. 터미널 두 개를 열어 각각 실행합니다.

```powershell
# 터미널 1: 주민 앱  http://localhost:5173
pnpm --filter @jori/web-user dev

# 터미널 2: 관리자 앱  http://localhost:5174
pnpm --filter @jori/web-admin dev
```

> **참고** 두 앱이 같은 기본 포트(5173)를 쓰려 하므로 두 번째 앱은 자동으로 다른 번호를 잡을 수 있습니다. 포트를 고정하려면 아래 직접 실행 방법을 쓰세요.

pnpm 실행기가 막히는 PC에서는 설치된 Node로 직접 띄웁니다. 아래 명령으로 두 앱이 각각 5173, 5174에서 응답하는 것을 확인했습니다.

```powershell
cd apps\web-user
node .\node_modules\vite\bin\vite.js --host 127.0.0.1 --port 5173 --strictPort

cd apps\web-admin
node .\node_modules\vite\bin\vite.js --host 127.0.0.1 --port 5174 --strictPort
```

종료는 각 터미널에서 Ctrl+C입니다.

## 5. 방법 B. 실제 API와 DB로 띄우기

> **참고** 이 방법은 순서가 중요합니다. 개발 DB에 최초 설정이 되어 있지 않으면 워커는 시작 직후 멈춥니다(확인함). API도 운영묶음을 찾아야 하는 요청에서는 오류를 내도록 되어 있습니다(소스 기준). 처음 준비를 마친 PC에서는 5.1·5.2·5.6·5.7절을 손으로 하는 대신 5.8절의 파일로 켜고 끌 수 있습니다.

### 5.1 개발 DB 켜기

```powershell
# 최초 한 번만 (데이터 폴더와 비밀번호 파일을 만듭니다)
.\scripts\db\mariadb-dev.ps1 init

# 켜기 / 상태 / 끄기
.\scripts\db\mariadb-dev.ps1 start
.\scripts\db\mariadb-dev.ps1 status
.\scripts\db\mariadb-dev.ps1 stop
```

DB가 꺼져 있으면 DB가 필요한 시험이 조용히 건너뛰어집니다. 날짜가 바뀐 뒤에는 먼저 켜져 있는지 확인하세요.

### 5.2 환경변수 설정 (PowerShell)

API, 마이그레이션, 최초 설정, 워커를 실행하는 터미널마다 아래를 먼저 실행합니다. 비밀번호는 화면에 출력되지 않습니다.

```powershell
$cred = Get-Content "$env:USERPROFILE\dev-tools\mariadb-credentials.json" -Raw -Encoding UTF8 | ConvertFrom-Json
$pw = [uri]::EscapeDataString($cred.appPassword)
$env:JORI_DATABASE_URL = "mysql+pymysql://$($cred.appUser):$pw@127.0.0.1:$($cred.port)/jori_dev"
$env:JORI_SITE_ID = "jori-dev"      # 이 PC의 jori_dev에 있는 사이트 ID. 새 DB라면 5.4절의 --site-id와 같은 값
$keyFile = "$env:USERPROFILE\dev-tools\jori-dev-secret.txt"      # 비밀키 파일(저장소 밖). 없으면 한 번 만든다
if (-not (Test-Path $keyFile)) { -join ((48..57) + (65..90) + (97..122) | Get-Random -Count 48 | ForEach-Object { [char]$_ }) | Set-Content -NoNewline -Encoding ASCII $keyFile }
$env:JORI_SECRET_KEY = (Get-Content $keyFile -Raw).Trim()
$env:JORI_COOKIE_SECURE = "0"        # http로 개발하므로 보안 쿠키를 끈다
$env:JORI_ENVIRONMENT = "development" # 꼭 지정한다. 없으면 API·워커가 켜지지 않는다
$dev = "$env:USERPROFILE\dev-tools\jori-files"; New-Item -ItemType Directory -Force $dev | Out-Null
$env:JORI_FILE_ROOT = $dev                          # 첨부 저장 폴더 (저장소 밖)
$env:JORI_WORKER_STATUS_FILE = "$dev\worker-status.json"
```

- `JORI_SECRET_KEY`는 위 파일에 한 번 만들어 두고 계속 같은 값을 씁니다. 32자 미만이면 기동을 거절합니다. 휴대전화번호 암호화 키로도 쓰이므로 지우거나 바꾸면 저장된 번호를 읽을 수 없습니다. 이 PC의 파일은 마이그레이션 0005가 기존 회원 전화번호를 암호화할 때 쓴 키입니다. 저장소에는 넣지 마세요.
- `JORI_SITE_ID`는 5.4절의 `--site-id`와 같아야 합니다.
- `JORI_ENVIRONMENT`는 꼭 지정합니다. 없으면 API와 워커가 켜지지 않습니다. `development`는 PG·문자·파일 검사에 모의 어댑터를 쓰고, `production`에서는 모의 어댑터를 거절합니다.

### 5.3 DB 구조 만들기 (마이그레이션)

```powershell
cd apps\api
uv run alembic upgrade head
```

이 PC의 `jori_dev`는 2026-11-24에 `0005`로, 2026-11-26에 `0006`(시설 사진의 소유자 열)으로 올려 지금은 최신입니다. 0006을 올리기 전 백업은 `%USERPROFILE%\dev-tools\backup\jori_dev-before-0006-20261126.sql`입니다. 0005를 올리기 전 백업은 `%USERPROFILE%\dev-tools\backup\jori_dev-before-0005-20261124.sql`입니다. 0005는 휴대전화번호를 암호화하는 이행이라 위의 `JORI_SECRET_KEY`가 환경에 있어야 합니다. 현재 상태 확인은 `uv run alembic current`입니다. uv 실행기가 막히면 `.venv\Scripts\python.exe -m alembic ...`을 씁니다.

### 5.4 최초 설정 (bootstrap, 한 번만)

이 PC의 `jori_dev`는 이미 최초 설정이 되어 있어 이 단계가 필요 없고, 실행하면 이미 관리자가 있다며 거절합니다. 아래는 새 DB를 만들 때의 절차입니다.

운영묶음, 행정동, 최초 관리자를 한 번에 만듭니다. 이미 관리자가 있으면 아무것도 만들지 않고 거절합니다.

```powershell
# 행정동 명단 파일 만들기 (한 줄에 하나. 아래는 개발용 예시 이름이며 실제 명단은 기관 자료를 씁니다)
Set-Content -Encoding UTF8 "$dev\dongs.txt" "예시동1","예시동2"

uv run python -m app.tools.bootstrap --site-id jori-dev --bundle-name "조리읍 개발용" --site-name "조리읍 개발용" --url https://localhost --dongs-file "$dev\dongs.txt" --admin-id devadmin --admin-name "개발 관리자"
```

- 비밀번호는 프롬프트에서 두 번 입력합니다. 12자 이상, 영문 대문자·소문자·숫자·기호 중 3종류입니다.
- `--url`은 `https://`로 시작해야 검사를 통과합니다. 개발에서는 저장만 되는 값이라 `https://localhost`로 둬도 됩니다.
- 관리자 아이디는 영문으로 시작하는 4~20자(영숫자, `.`, `_`, `-`)입니다.
- 행정동 이름은 중복 없이 40자 이내입니다.

### 5.5 개발용 주민 계정 만들기

이 PC에는 `devmember`가 이미 있습니다. 새 주민 계정이 필요할 때 씁니다. 실제 API 모드에서 로그인할 주민 계정을 만듭니다. 문자 인증과 약관 동의 없이 DB에 직접 넣는 개발용 도구이며, 5.2절의 환경변수가 설정된 터미널에서 5.4절의 최초 설정을 마친 뒤 실행합니다.

```powershell
cd apps\api
uv run python -m app.tools.dev_member --login-id devmember3 --name "개발회원3" --phone 01012345678 --email dev@example.com
```

- 비밀번호는 프롬프트에서 두 번 입력합니다. 10~64자입니다. 여러 계정을 만들 때는 `--password-stdin`을 붙여 표준입력 한 줄로 줄 수 있습니다.
- 아이디는 소문자 영문으로 시작하는 4~20자(소문자·숫자·`.`·`_`·`-`)입니다. 이름은 100자 이내입니다.
- `--phone`(숫자만, 01로 시작하는 10~11자리)과 `--email`은 생략할 수 있습니다. 번호는 가입과 같은 방식으로 암호화해 저장합니다.
- 같은 아이디가 있거나, 운영묶음이 없거나(5.4절 전), 입력이 틀리면 아무것도 만들지 않고 종료 코드 3으로 끝납니다.
- `JORI_ENVIRONMENT=production`이면 비밀번호를 묻기 전에 거절합니다. 이 도구는 개발 PC 전용이며 운영 DB에는 쓰지 않습니다.
- 가입을 통과한 계정이 아닙니다. 문자 인증과 약관 동의 이력이 없습니다. 신청·결제·환불 경로는 동의 이력을 쓰지 않습니다.

만든 뒤 주민 앱은 5.7절과 같은 방식으로 5173 포트에 띄우고 `http://localhost:5173/login`에서 로그인합니다.

### 5.6 API와 워커 띄우기

```powershell
# 터미널 1: API  http://127.0.0.1:8000
cd apps\api
uv run uvicorn app.main:app --host 127.0.0.1 --port 8000

# 터미널 2: 워커 (자치회마다 하나만, 같은 환경변수 필요)
cd apps\api
uv run python -m app.worker
```

상태 확인은 `http://127.0.0.1:8000/api/health`입니다. 워커가 떠 있지 않으면 `503 degraded`가 정상입니다. 모든 주기 작업이 첫 실행을 마치면(기동 후 약 20~40초) `ok`(200)가 됩니다.

> **참고** API 문서 화면(`/docs`)은 꺼져 있습니다. 계약은 `packages/api-client/openapi.json`(생성 파일)에서 봅니다.

### 5.7 화면을 실제 API에 연결

웹 앱은 `/api` 요청을 `127.0.0.1:8000`으로 넘기도록 되어 있습니다. 모의 서버만 끄면 됩니다.

```powershell
$env:VITE_API_MODE = "live"
cd apps\web-admin
node .\node_modules\vite\bin\vite.js --host 127.0.0.1 --port 5174 --strictPort
```

관리자 앱은 5.4절에서 만든 관리자(이 PC는 `devadmin`)로 `http://localhost:5174/login`에서 로그인합니다. 주민 앱은 같은 방식으로 `--port 5173`, `apps\web-user`에서 띄우고 5.5절에서 만든 계정(이 PC는 `devmember`)으로 `http://localhost:5173/login`에서 로그인합니다.

### 5.8 파일을 두 번 눌러 켜고 끄기

저장소 폴더에 파일 두 개가 있습니다. Windows 개발 PC의 실제 API 모드(개발 DB `jori_dev`)에서만 씁니다.

| 파일 | 하는 일 | 실제 처리 |
|---|---|---|
| `프로그램_켜기.bat` | DB, API, 워커, 사용자 화면, 관리자 화면을 켜고 브라우저에 두 화면을 엶 | `scripts\start-all.ps1` |
| `프로그램_끄기.bat` | 화면, API, 워커를 끄고 DB를 정상 종료 | `scripts\stop-all.ps1` |

**처음 한 번 해 둘 것**. 켜기 파일은 아래를 대신하지 않습니다.

- 3절의 도구 설치와 `pnpm install`, `apps\api`에서 `uv sync`
- 5.1절의 `init` (개발 DB와 비밀번호 파일)
- 5.2절의 비밀키 파일 `jori-dev-secret.txt`
- 5.3절의 마이그레이션과 5.4절의 최초 설정. 켜기 파일이 사이트 ID를 `jori-dev`로 정하므로 최초 설정도 `--site-id jori-dev`로 합니다.
- 주민 계정이 필요하면 5.5절

**켜기**

1. `프로그램_켜기.bat`를 두 번 누릅니다.
2. 창에 `[1/5]`부터 `[5/5]`까지 차례로 나옵니다. `모두 켜졌습니다.`가 나오면 브라우저에 두 화면이 열립니다.
3. Enter 키를 누르면 이 창만 닫히고 시스템은 계속 켜져 있습니다.

- 작업 표시줄에 최소화된 `수강시스템 ... (닫지 마세요)` 창이 네 개 생깁니다(서버, 워커, 사용자 화면, 관리자 화면). 창을 닫으면 그 서비스가 꺼집니다. DB는 창이 없습니다.
- 환경변수는 파일이 5.2절의 값으로 정하고 화면은 실제 API(`VITE_API_MODE=live`)에 연결하므로 따로 설정하지 않습니다.
- 이미 켜진 것은 건너뜁니다. 그래서 **모의 서버 모드의 화면(4절)이 켜져 있으면 먼저 끄고** 켭니다. 그대로 두면 그 화면이 모의 모드로 남거나, 켜기 파일이 주소가 응답하지 않는다며 멈춥니다.
- API와 워커는 코드를 고쳐도 다시 읽지 않습니다. 끄고 다시 켭니다.

**끄기**

1. `프로그램_끄기.bat`를 두 번 누릅니다.
2. `모두 꺼졌습니다.`를 확인하고 Enter 키를 누릅니다.

- 끄는 대상은 켜기 파일이 만든 서비스 창, 이 저장소의 API와 워커(5.6절처럼 직접 켠 것 포함), 5173·5174 포트의 이 센터 화면(4절과 5.7절처럼 직접 켠 것 포함), 개발 DB입니다.
- 직접 연 터미널 창은 닫지 않고 그 안의 서버만 끕니다. 다른 포트에 띄운 화면은 끄지 않습니다.
- 같은 포트를 쓰는 다른 프로그램은 끄지 않고 포트 번호를 알려 줍니다.
- 프로세스를 강제로 끝내므로 개발 PC에서만 씁니다. **DB를 쓰는 시험이 도는 중에는 실행하지 않습니다.** DB가 함께 꺼집니다.

## 6. 시험 실행

| 대상 | 명령 (실행 위치) | 비고 |
|---|---|---|
| 전체 | `pnpm check` (저장소 루트) | 린트, 타입, 단위, 빌드, 브라우저 시험(Edge) 순서. 20분 이상 걸릴 수 있음 |
| API | `uv run pytest -q` (apps\api) | DB가 꺼져 있으면 DB 시험이 건너뛰어짐. 건너뜀 수를 꼭 확인 |
| API 린트·타입 | `uv run ruff check .`, `uv run mypy app tests` (apps\api) |  |
| DB 필수 검증 | `JORI_REQUIRE_DB=1`을 설정하고 pytest | DB 없는 결과를 통과로 보지 않기 위함 |

> **참고** DB 시험은 `jori_test`만 초기화합니다. `JORI_TEST_DATABASE_URL`에 개발·운영 DB를 지정하지 마세요.

## 7. 문제가 생겼을 때

| 증상 | 원인과 조치 |
|---|---|
| `pnpm`이 하위 pnpm을 못 찾는다는 오류 | 이 PC의 실행기 제한입니다. 4절의 `node ...vite.js`나 각 앱의 `node_modules\.bin\vitest`, `tsc`를 직접 실행합니다. |
| 포트가 이미 사용 중이라는 오류 | `--strictPort` 때문에 멈춘 것입니다. 이전에 띄운 서버를 종료하거나 다른 포트를 씁니다. |
| API가 `필수 환경변수가 없습니다`로 종료 | `JORI_ENVIRONMENT`, `JORI_DATABASE_URL`, `JORI_SITE_ID`, `JORI_SECRET_KEY`를 같은 터미널에 설정했는지 확인합니다. |
| `/api/health`가 503 | 워커가 없으면 정상입니다. 워커를 띄우고 첫 실행 뒤에 다시 확인합니다. |
| 워커가 시작하자마자 오류로 종료 | 운영묶음이 없는 것입니다. 5.4절 최초 설정을 하고 `JORI_SITE_ID`가 같은지 확인합니다. |
| 개발용 계정 도구가 `운영묶음이 없습니다`로 종료 | 5.4절의 최초 설정을 하지 않았거나 `JORI_SITE_ID`가 최초 설정의 `--site-id`와 다른 것입니다. 종료 코드는 3입니다. |
| 로그인이 계속 실패 | 아이디·비밀번호를 확인합니다. 5회 실패하면 잠기며 화면 문구는 같습니다. 모의 서버는 쪽을 새로 열면 풀립니다. |
| DB 시험이 전부 건너뛰어짐 | 개발 DB가 꺼져 있습니다. `mariadb-dev.ps1 start` 후 다시 실행합니다. |
| 켜기 파일이 `준비되지 않은 것이 있습니다`로 멈춤 | 함께 나온 목록의 항목이 없는 것입니다. 5.8절의 처음 한 번 해 둘 것을 합니다. |
| 켜기 파일이 `다음 주소가 응답하지 않습니다` 또는 `워커가 켜지지 않았습니다`로 멈춤 | 작업 표시줄의 해당 `수강시스템` 창에서 오류 글을 읽습니다. 워커는 최초 설정(5.4절)이 없으면 멈춥니다. 모의 모드 화면이 남아 있어도 이렇게 될 수 있습니다. 끄기 파일을 실행하고 원인을 고친 뒤 다시 켭니다. |
| 끄기 파일이 포트를 아직 쓰는 프로그램이 있다고 알림 | 수강시스템의 것으로 확인되지 않은 프로그램입니다. 작업 관리자에서 확인합니다. |

## 8. 이 문서의 확인 범위

2026-11-24에 이 PC에서 직접 실행해 확인한 것과 하지 못한 것을 구분해 둡니다. 켜기·끄기 파일 행은 2026-11-26에 확인했습니다.

| 항목 | 상태 | 근거 |
|---|---|---|
| 모의 서버 두 앱 기동 | 확인함 | `node ...vite.js`로 5173, 5174에서 응답(200)하고 종료까지 확인 |
| 모의 계정 값 | 확인함 | 소스와 단위 시험, 브라우저 시험(e2e 주민 246건, 관리자 389건 통과. 관리자 2건은 단독 재실행에서 통과, 2026-11-23)이 같은 값으로 로그인 |
| API 기동 | 확인함 | 개발 DB에 연결해 기동, 세션 조회 200, `/api/health` 503(워커 없음) 응답 |
| 워커 기동 | 확인함 | 최초 설정이 없는 DB에서는 시작 직후 중단됨을 확인했고, 설정이 된 `jori_dev`에서는 정상 기동해 모든 주기 작업이 첫 실행을 마친 뒤 `/api/health`가 200 `ok` |
| 마이그레이션 실행 | 확인함 | 이 PC의 `jori_dev`를 백업한 뒤 `0004`에서 `0005`로 올림. 기존 회원 2명의 행이 유지되고 전화번호 컬럼이 암호문·검색해시로 바뀐 것을 확인 |
| 최초 설정(bootstrap) 실행 | 이 PC에서는 불필요 | `jori_dev`에는 2026-11-20에 만든 사이트·관리자가 이미 있음. 실행하지 않았고 입력 규칙은 소스를 읽어 적었으며 이 도구의 시험은 저장소에 있음 |
| 개발용 주민 계정 도구 | 일부 | 저장소 시험 20건(실제 MariaDB)과 변이 검사 6건으로 확인. 이 PC의 `jori_dev`에서는 이 도구로 계정을 만들지 않고 기존 `devmember`의 비밀번호를 재설정함. 운영묶음이 없을 때 거절하는 경로만 실제 DB에서 확인 |
| 실제 API 모드 로그인 | 확인함 | 실제 API·DB에 HTTP로 주민 `devmember`, 관리자 `devadmin` 로그인 성공(200)과 세션 확인, 틀린 비밀번호는 401. 브라우저 화면에서의 로그인은 직접 확인하지 않음 |
| `pnpm --filter ... dev` 명령 | 일부 | 2026-11-26에 Git Bash에서 두 앱이 `::1`로 열리는 것을 확인. 다른 셸에서의 실행은 확인하지 못함 |
| 켜기·끄기 파일 | 확인함 | 파일을 명령으로 실행해 확인. 켜기는 모두 꺼진 상태에서 기동. 끄기는 켜기 파일, 5.6·5.7절 방식, `pnpm dev`로 켠 것을 끄고 다른 프로그램은 남김. 탐색기에서 마우스로 두 번 누르기와 새 PC의 처음 준비는 확인하지 않음 |

운영 서버(Ubuntu) 배포는 이 문서의 범위가 아닙니다. `deploy/README.md`를 따릅니다.
