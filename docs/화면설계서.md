## 1. 작성 기준

### 1.1 범위
- 원천 추적표의 화면 ID 115개(주민 68, 관리자 47)를 모두 담았다. 여기에 ID 제안 화면 2개를 더해 주민 70개, 합계 117개다.
- ★ 표시 화면 22개는 와이어프레임을 그렸다. 나머지는 구성요소·동작·상태 명세로 정의한다.
- 원천에 ID가 없는 화면은 `[ID 제안]`으로 표시했다. 원천 ID 공백(USR-EZY-003~005, ADM-SYS-003·006)은 임의로 채우지 않았다.

### 1.2 표기
| 표기 | 의미 |
|---|---|
| `[버튼]` | 버튼 |
| `(입력)` | 입력 필드 |
| `▼` | 선택 상자 |
| `☐ / ☑` | 체크박스 |
| `◉ / ○` | 라디오 |
| `{값}` | API 값 |
| `P` 접미 | 팝업·등록/수정 화면 (예: ADM-EDU-001P) |
| `S` 접미 | 설정 화면 |

### 1.3 공통 상태 (모든 데이터 화면에 적용)
| 상태 | 표현 | 규칙 |
|---|---|---|
| 로딩 | 영역 스켈레톤 + `aria-busy` | 300ms 이내 응답은 스켈레톤 생략 |
| 빈 상태 | 안내 문장 + 다음 행동 링크 | 자료를 임의로 만들지 않는다 (NF-QUR-001) |
| 0건 검색 | "조건에 맞는 강좌가 없습니다" + `[조건 지우기]` | 통신 실패와 문구를 구분한다 (FN-013) |
| 오류 | "정보를 불러오지 못했습니다" + `[다시 시도]` + 문의 전화 | |
| 권한 없음 | "이용 권한이 없습니다" + 로그인/이전 화면 | 404와 403 문구를 구분하되 타인 리소스는 404 |
| 확인 필요 | 값 자리에 "확인 필요" 회색 텍스트 | 미확정 운영값 |

### 1.4 시각·접근성 기준
- 주민 기본 화면은 LH 참고 시안의 여백·정렬·색상 방향을 따른다. 반복 카드·다색을 피하고 목록과 문장을 쓴다(NF-QUR-002).
- 접수상태 배지는 색과 텍스트를 함께 쓴다. `접수중`, `접수예정`, `대기접수`, `마감`, `폐강`(NF-QUR-004).
- 모든 폼은 label 연결, 필수는 "(필수)" 텍스트, 오류는 입력 아래 문장 + 첫 오류로 초점 이동.
- 모바일(<768px): 검색 조건 세로 배치, 표 → "항목명: 값" 목록, 상세 하단 고정 신청 요약, 신청/결제 버튼 전체 폭, 체크 영역 44px 이상(NF-QUR-005).
- 쉬운 화면: 본문 20px, 보조 18px, 버튼 높이 56px, 아이콘 + 행동 문구(NF-QUR-003).

### USR-CRS-002 접수중 · 접수예정 강좌
- 구성: 탭 `[접수중] [접수예정]`, 그 외 USR-CRS-001과 같은 목록 컴포넌트. 접수예정 탭은 접수 시작일 오름차순.
- 빈 상태: "현재 접수중인 강좌가 없습니다. 접수예정 강좌를 확인해 보세요."

### USR-CRS-003 분야별 강좌
- 구성: 분야 탭(센터 강좌분류 표시 순서), 분야 요약(접수상태·접수기간·교육기간), 목록.
- 홈 강좌 안내에서 진입 시 해당 분야 선택. 같은 API·같은 기준으로 홈과 값이 일치해야 한다(FN-005).

### USR-CRS-005 강의계획서
- 구성: 강좌명·강사·정원 요약, 강의계획 본문, 계획서 파일 `[원본 내려받기 (PDF)]`, `[강좌 상세로]`.
- 회차별 표(`회차 | 교육내용 | 준비물`)는 강의계획 본문 안에 서술된 경우에만 보인다. 별도 회차 테이블은 없다([ADR-027](ADR.md#adr-027), PRD Q20).
- 자료 없으면 "미수록" 1행(FN-015).

### USR-CRS-006 수강 및 결제 안내
- 섹션: ① 온라인 신청 절차(회원가입 → 로그인 → 휴대전화 본인확인 → 신청 → 10분 내 결제) ② 결제수단(카드·실시간 계좌이체) ③ 10분 결제기한·2분/1분 전 알림·만료 시 다음 순번 자동 배정 ④ 대기 신청 설명 ⑤ 감면 대상·사전 증빙 절차 ⑥ "이전 운영 방식" 상자(방문 접수·계좌이체, 회색 배경) ⑦ 공식 모집 안내 첨부.
- 이전 방식 상자는 "2026년 이전 운영 방식이며 현재는 온라인으로만 접수합니다" 문장을 맨 앞에 둔다(FN-016, NF-QUR-006).

### USR-CRS-007 환불 및 휴강일 안내
- 섹션: 환불 기준표(개강 전 전액 / 개강 후 당월분 제외), 환불 절차(신청 → 검토 → 집행 → 완료, 심사 3영업일·집행 7영업일 목표), 휴강일(주말·공휴일 미운영), 폐강 기준(정원 60% 미만), 공식 안내 링크.

### USR-TCH-001 강사현황 / USR-TCH-002 강사 소개
- 001: 검색(강사명·강좌명), 목록 `강사명 | 분야 | 담당 강좌 | 소개(2줄)`. 승인·공개 강사만.
- 002: 소개·경력·자격(미수록 시 "등록된 정보가 없습니다"), 담당 강좌 목록 링크, `[강사 목록]`. 심사 증빙 노출 없음(FN-018).

### USR-TCH-003 강사등록신청(모집공고 목록) / USR-TCH-004 모집공고 상세
- 003: 목록 `상태 | 공고명 | 모집기간 | 모집인원`, `[내 지원내역]`.
- 004: 본문·첨부, 모집기간·대상·지원 방법·필요 자료. 모집중 + 온라인 접수 채택일 때만 `[지원하기]`. 마감 공고는 "모집이 마감되었습니다"(FN-019).

### USR-TCH-005 강사신청서 작성
- 필드: 이름·휴대전화(읽기 전용), 희망 강좌명(필수), 희망 분야 ▼, 경력·강의소개, 강의계획서·증빙 첨부, 공개 희망 ◉/○, ☐ 제출 내용 확인(필수).

### 회원 (USR-MEM-001 ~ 010)

#### USR-MEM-001 로그인
- 필드: 아이디, 비밀번호(마스킹, 보기 토글), `[로그인]`, 링크 회원가입·아이디 찾기·비밀번호 재설정.
- 오류: "아이디 또는 비밀번호가 맞지 않습니다", 잠금 시 "로그인을 5회 잘못 시도하여 {HH:mm}까지 로그인할 수 없습니다", 탈퇴 계정은 일반 실패 문구.
- 성공 시 `returnUrl`(같은 사이트 경로만 허용) 또는 메인.

#### ★ USR-MEM-002 ~ 004 회원가입
```
[1 약관동의] ─ [2 본인확인] ─ [3 정보입력] ─ [4 완료]      ← 현재 단계 강조 + "2/4단계" 텍스트

── 1 약관동의 (MEM-002) ──────────────────────────────
☐ 전체 동의 (선택 항목 포함)
☐ (필수) 이용약관 동의            [전문 보기]  v{버전} 시행 {날짜}
   └ 요약: 서비스 이용 조건, 회원의 의무 …
☐ (필수) 개인정보 수집·이용 동의   [전문 보기]
☐ (선택) 센터 소식 문자 수신 동의
                                   [다음] ← 필수 2개 체크 전 비활성 + 이유 문구

── 2 본인확인 (MEM-003) ──────────────────────────────
☐ (필수) 휴대전화 본인확인 진행에 동의합니다
이름        (            )
휴대전화    (010-    -    )   [인증번호 받기]   ← 재전송 60초 카운트
인증번호    (      )  04:32   [확인]            ← 5분, 5회 오류 시 재발급 안내
                                   [다음]

── 3 정보입력 (MEM-004) ──────────────────────────────
이름         홍길동        (본인확인 값, 수정 불가)
휴대전화     010-****-5678 (수정 불가)
아이디       (            ) [중복 확인]  ✓ 사용할 수 있습니다
비밀번호     (            )  10~64자
비밀번호 확인 (            )
이메일       (            )  (선택)
소속 동       [조리읍 ▼]  ※ 선택만으로 우선접수 자격이 인정되지 않습니다 (관리 기준 동, 선택)
                                   [가입하기]
```
- 출생연도·성별 입력란은 없다. 연령·성별 통계는 기관 제공 집계자료를 쓴다(FN-060, PRD Q7).
- 거주지 확인 결과(확인완료·재확인필요)는 가입 화면에서 입력하지 않는다. 센터 담당자가 확인한 뒤 회원 정보에 반영하며 마이페이지에는 상태 문구만 보인다(PRD Q5).
- 동의 문안 버전은 화면에 표시하고 가입 시 같은 버전 ID를 저장한다(FN-030).
- 아이디 중복은 확인 버튼과 최종 저장에서 두 번 검사. 저장 시 충돌이면 아이디 필드 오류로 되돌리고 다른 입력은 유지(FN-029).

#### USR-MEM-005 회원가입 완료
- "가입이 완료되었습니다", `[로그인]`, `[강좌 둘러보기]`.

#### USR-MEM-006 아이디 찾기
- 이름·휴대전화 → 인증번호 → 결과 "가입하신 아이디는 `ho*****` 입니다" → `[로그인]` `[비밀번호 재설정]`.
- 불일치 시에도 발송 단계 문구는 동일("일치하는 정보가 있으면 인증번호를 보냈습니다")(FN-061).

#### USR-MEM-007 비밀번호 재설정
- 아이디·이름·휴대전화 → 인증번호 → 새 비밀번호·확인(10~64자) → "비밀번호를 변경했습니다. 모든 기기에서 로그아웃되었습니다" → `[로그인]`(FN-062).

#### USR-MEM-008 이용약관 / 009 개인정보처리방침 / 010 이메일무단수집거부
- 상단 `시행일 {날짜} · 버전 {v}` + 이전 버전 선택 ▼. 검토 상태면 "확정 전 검토 문안입니다" 배지. 조항별 목차 앵커.
- 개인정보처리방침의 책임자·부서·연락처는 실제 값만. 없으면 "확인 필요"(FN-055, FN-072).

- 004: 조건 심사상태·공개상태·검색어. 열 `지원번호 | 지원자 | 희망 강좌 | 접수일 | 심사상태`.
- 004P: 지원 내용·증빙(내려받기 감사기록), 심사 결과 ◉승인 ○반려 ○활동중지, 사유, 공개 여부, 검토 메모("개인정보를 입력하지 마세요" 안내). 승인해도 강좌 배정·관리자 권한은 자동 부여되지 않음 문구(FN-051).

#### ADM-EDU-005 / 005P 센터 · 강의실
- 005: 트리(센터 > 강의실), 사용 여부 배지.
- 005P: 구분, 상위 시설, 시설명, 층, 주소·좌표(센터), 공개 여부, 사용 여부. 사용 중지 시 "기존 일정은 유지, 새 일정 배정 불가" 안내(FN-050).

#### ADM-EDU-006 / 007 출석 현황 · 상세
- 006: 조건 기수·강좌·수업일·입력상태(전체/입력중/완료). 열 `강좌 | 수업일 | 회차 | 강사 | 출석/결석/미체크 | 입력상태`. CSV 없음.
- 007: 담당강사·출석부 ID, 명단 `이름 | 신청번호 | 회원상태 | 출석상태`. 조회 전용, 연락처·생년·결제정보 없음(FN-064).

### 신청·결제

#### ADM-PAY-001 / 001P 수강신청 관리 · 상세
- 001: 조건 기수·강좌·신청상태·결제상태·기간·검색어(신청번호·이름). 열 `신청번호 | 강좌 | 신청자(마스킹) | 신청상태 | 결제상태 | 환불상태 | 접수시각`.
- 001P: 신청 원장 전체 이력(접수순번·배정·기한·상태 전이), 연결 결제·환불, 멱등 재요청 기록. 관리자의 상태 직접 변경 기능 없음(방문·유선 환불 접수는 환불 화면에서).

#### ADM-PAY-002 / 002P 대기 · 자리 배정
- 002: 강좌별 `정원 | 점유 | 대기 수 | 다음 대기 순번 | 최근 승격 시각`.
- 002P: 대기자 순번 목록, 승격 이력(배정시각·기한·SMS 결과). 수동 승격 버튼 없음(자동 배정, FN-035).

#### ADM-PAY-003 결제 · 거래 대조
- 조건 결제상태(확인중 우선 정렬), 기간, 결제수단. 열 `주문번호 | 신청번호 | 금액 | 수단 | 상태 | 요청시각 | PG 승인시각 | 재조회 횟수`. 충돌 통보 건 별도 탭.

#### ADM-PAY-004 환불 검토
- 조건 환불상태·요청 주체(회원/관리자 대리 접수)·기간. 열 `환불번호 | 신청번호 | 강좌 | 요청액 | 상태 | 접수일 | 경과 영업일`. 3영업일 초과 강조. `[방문·유선 환불 접수]` 버튼. 기준액은 승인 시 산정해 상세에 표시한다(별도 컬럼 없음, [TDD 5.6](TDD.md)). 접수 채널 구분은 PRD Q29.

#### ADM-PAY-005 / 005P / 006 감면
- 005: 사전 심사 신청 목록 `회원 | 기수 | 감면 유형 | 증빙 수 | 신청일 | 상태`.
- 005P: 증빙 열람(감사기록), 심사 ◉승인 ○반려(반려 사유 필수), 승인 유효기간. 승인·반려 후 내용과 증빙은 수정할 수 없고 재심사는 `[재심사]`로 새 심사건을 만든다(RDCT-BFHD-01). 신청에 적용된 판정·금액은 006 이력에 새 행으로 쌓인다(FN-038).
- 감면 유형은 기초생활보장 수급자 본인·국가유공자 본인·등록 장애인 본인 3종이며 조리읍 거주 확인 회원만 대상이다. 심사 권한 코드는 PRD Q21.
- 006: 판정 이력 `판정일시 | 회원 | 기수 | 결과 | 사유 | 처리자 | 증빙 | 사용 신청`.

### 회원·게시

#### ADM-MBR-001 / 001P 회원 관리
- 001: 조건 검색어(아이디·이름), 이용상태. 열 `회원 ID | 이름(마스킹) | 연령대 | 거주범위 | 가입일 | 이용상태`.
- 001P: 회원 기본 정보 조회, 신청·결제 요약, 이용제한/탈퇴 검토 사유 기록(검토 상태와 처리 완료 구분), 이름 변경 요청 승인. 일반 정보 수정 필드 없음(FN-065).

#### ADM-MBR-002 / 002P / 002S 게시물 · 게시판
- 002: 게시판 선택 → 게시물 목록, 상단공지 지정.
- 002P: 제목, 본문(에디터, 허용 태그만), 상단공지, 게시기간, 첨부 업로드(자료실 PDF 등, 원천 시안에 필드 없음 → 추가 확인).
- 002S: 게시판별 회원 작성·답변·첨부·비공개 허용·사용 여부(AU.BBS_W 권한)(FN-052).

#### ADM-MBR-003 / 003P 문의 · 답변
- 003: 조건 답변상태·분류. 비공개 글은 권한 범위 안에서만 본문 노출.
- 003P: 문의 본문·첨부, 답변 작성(1단계), 관련 화면 링크 입력.

#### ADM-MBR-004 / 004P 홈 · 센터 콘텐츠
- 004: 콘텐츠 유형 탭(비주얼·배너·팝업·연혁·센터소개·연락처·안내).
- 004P: 제목, 본문, 링크, 이미지 업로드(원천 시안에 필드 없음 → 추가 확인), 게시기간, 게시 여부, 원본 확인일. 연락처 유형은 수강문의·센터대표·행정복지센터대표·운영시간·주차·주소 구조 폼(FN-011, FN-054).

#### ADM-MBR-005 / 005P 약관 · 동의문
- 005: 문안 종류별 버전 목록 `버전 | 시행일 | 상태(검토/확정/게시) | 게시일 | 동의 회원 수`.
- 005P: 새 버전 작성(이전 버전 복제), 시행일, 필수 동의 여부. 게시 후 수정 버튼 없음 → `[새 버전으로 개정]`(FN-055).

#### ADM-MBR-006 첨부파일
- 조건 소유 업무·검사상태. 열 `파일명 | 소유 업무 | 크기 | 검사상태 | 등록일`. 차단 파일 사유, 내려받기 감사기록(RQ-SER-NF-002).

- 파기 예정 목록 `대상 유형 | 건수 | 기준일 | 예정일`, 상세(비식별 처리 항목), `[실행]`(확인 필요(Q21), 실행 결과 감사기록). 정산자료는 대상에서 제외됨을 표시(FN-032, RQ-SER-NF-006).
