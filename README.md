# 조리읍 주민자치센터 수강시스템

경기도 파주시 조리읍 주민자치센터의 강좌 조회·수강신청·결제·환불 시스템입니다. 주민은 기본 화면과 쉬운 화면(고령·저시력 이용자용) 중 골라 쓰고, 센터 직원은 관리자 화면에서 강좌와 접수를 운영합니다.

> **현재 상태(2026-11-19)** 주민·관리자 화면과 FastAPI·MariaDB 업무 구현이 진행돼 인증·신청·결제·환불·게시판·집계·보존 작업이 연결돼 있습니다. 개발 화면은 기본적으로 모의 서버(MSW)를 사용하며 `VITE_API_MODE=live`로 실제 API를 사용합니다. 실제 PG·SMS 연동과 운영 배포·복구·부하 검증은 남아 있습니다. 세부 잔여 작업은 `checklist.md`와 최신 ADR을 확인합니다.

## 검증 현황

`pnpm check`가 린트, 타입 검사, 단위 시험, 빌드, 브라우저 시험(Edge, 접근성 axe 포함)을 모두 실행합니다. DB 시험이 건너뛰어졌다면 전체 검증 통과로 보지 않습니다. DB가 필수인 검증에서는 `JORI_REQUIRE_DB=1`로 실행합니다.

2026-11-19 소스 검증 당시 주민 399건·관리자 423건의 단위 시험이 통과했습니다. 후속 보완은 시험 DB 보호·워커 경합·로그 마스킹·작업별 감시·운영 설정을 별도 회귀 시험으로 검증합니다. DB 접속과 로컬 소켓이 차단된 환경의 통합·브라우저·ClamAV 검증은 미완료로 기록합니다. 실행별 결과는 `context-notes.md`를 확인합니다.
## 구성

```
apps/
  api/           FastAPI 업무 API·MariaDB 접근·마이그레이션·별도 프로세스 워커(app/worker)
  web-user/      주민 앱 (React, 기본 화면 + 쉬운 화면)
  web-admin/     관리자 앱 (React, 시안의 관리자 화면)
packages/
  ui/            시안 CSS와 공통 자원
  api-client/    OpenAPI에서 생성한 TypeScript 타입
docs/            PRD, TRD, ADR, TDD, 화면설계서, DB 스키마 설계안
```

계획 문서는 저장소 루트의 `intent.md`(확정 결정), `plan.md`(단계), `spec.md`(상세 명세와 결정 기록 DV1~), `checklist.md`, `context-notes.md`입니다. 기관에 보낼 스키마 변경 요청은 `docs/스키마_개정_요청서.md`에 모읍니다.

## 기술 스택

- **프런트엔드** React 18, TypeScript, Vite, React Router 7, TanStack Query 5
- **백엔드** Python 3.12, FastAPI, Pydantic 2 (패키지 관리 uv)
- **시험** Vitest, Testing Library, MSW, Playwright(+axe-core), pytest, ruff, mypy
- **목표 운영 환경** Ubuntu Server, MariaDB 10.11 (주민자치회마다 WAS·DB 분리)

## 시작하기

필요한 것은 Node.js 22.12 이상, pnpm 10, uv(Python 3.12)입니다. 브라우저 시험은 이 PC에 설치된 Microsoft Edge를 씁니다.

```powershell
pnpm install
pnpm --filter @jori/web-user dev        # http://localhost:5173 (모의 서버로 동작)
pnpm --filter @jori/web-admin dev       # 관리자 앱 (모의 서버로 동작)
pnpm check                              # 린트, 타입, 단위 시험, 빌드, 브라우저 시험을 모두 실행
```

개발 서버에서만 쓸 수 있는 보조 기능이 있습니다. 운영 빌드에는 들어가지 않으며, 섞이면 빌드가 실패합니다.

- `?view=easy` 쉬운 화면으로 전환합니다.
- `?mockNow=2026-09-08` 모의 시계를 접수 기간으로 옮겨 접수중 강좌와 수강신청 버튼을 봅니다.
- `?mockPay=success` 모의 결제 결과를 고릅니다(`success`, `failed`, `unknown`, `expired`).

모의 서버의 상태는 쪽을 새로 열면 처음으로 돌아갑니다. 시험 계정 정보는 저장소의 설계 문서(`spec.md`)에 있습니다.

## 운영 환경과 시험 DB 보호

- 운영 배포는 `JORI_ENVIRONMENT=production`을 명시합니다. PG·SMS·파일 검사에 `mock`이 남거나 보안 쿠키가 꺼져 있으면 기동을 거절합니다. 실제 PG·SMS 어댑터는 계약 후 구현해야 하므로 현재 소스는 운영 외부 연동을 완료한 상태가 아닙니다.
- 개발 기본 환경은 `development`이고 모의 연동을 유지합니다. 실제 API를 개발용 모의 PG로 연결하는 것과 실제 결제 서비스를 연결하는 것은 별개입니다.
- 시험은 `jori_test` DB만 허용합니다. `JORI_DATABASE_URL`의 앱 DB와 같은 대상이면 거절하고, 실제 접속 DB 이름을 확인한 뒤에만 테이블을 초기화합니다. `JORI_TEST_DATABASE_URL`에 개발·운영 DB를 지정하지 않습니다.
- 워커는 배포당 하나를 `python -m app.worker`로 실행합니다. 상태 파일 잠금은 한 프로세스 안의 작업 간 동기화이며 다중 워커 프로세스 실행은 지원하지 않습니다.
- `/api/health`는 주기 작업의 누락·실패·지연과 일일 작업의 예약 기한을 확인합니다. 주기 작업은 모두 첫 실행을 마쳐야 정상이고, 일일 작업은 첫 예약 시각까지 유예합니다. 지연 허용은 5분과 작업 주기 3회의 큰 값입니다.
- Windows의 pnpm 실행기가 작동하지 않으면 설치된 Node 도구를 직접 실행할 수 있습니다. 예를 들어 주민 앱 폴더에서 `node node_modules/vitest/vitest.mjs run`, API 폴더에서 `.venv/Scripts/python.exe -m pytest`를 사용합니다. API 계약 생성 후에 타입 검사를 실행합니다.

## 개발 원칙

- 일련번호는 22자리 숫자 문자열이며 JS 숫자로 바꾸지 않습니다.
- 금액·정원·결제기한·가능 여부·비공개 가림은 서버가 정하고 화면은 그대로 그립니다. 신청·결제·환불 요청에는 금액을 싣지 않습니다.
- 상태를 바꾸는 요청은 CSRF 토큰과 멱등키를 쓰고, 로그인·로그아웃 때 회원 전용 화면 캐시를 지웁니다.
- 접수·교육 상태는 서버가 판정하고 화면은 날짜를 비교하지 않습니다.
- 기본 화면과 쉬운 화면은 같은 API와 같은 쿼리 키를 씁니다.
- 새 기능은 시험을 먼저 쓰고, 접근성(KWCAG 2.2 AA) 검사를 단계마다 통과해야 합니다.
- 사용 허가가 확인되지 않은 청사 사진은 저장소에 넣지 않습니다.

## 문서

기능 요구와 결정의 근거는 `docs/`에 있습니다. 데이터 모델은 `docs/PRJ_2026_002_DB스키마_설계안.md`가 기준입니다.

전화번호별 OTP 재전송 제한은 ADR-095와 [적용 보고](docs/OTP_재전송제한_개정안.md)를 따른다. 기존 DB는 0002 추가 이행이 필요하고, 최초 전환·비밀키 교체 시 발급을 중지한 뒤 기존 OTP 만료를 위해 5분을 기다려야 한다. 현재 작업에서는 실제 DB 이행을 수행하지 않았다.
